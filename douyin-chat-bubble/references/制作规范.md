# 抖音气泡制作规范

核验日期：2026-10-16。适用：抖音 IM 聊天气泡资源与点九适配。

官方来源：[聊天气泡常见问题与制作规范](https://effect.douyin.com/content/pwik2f7v/pwdsypki#80c5b68b)。本次通过浏览器读取了官方全文。本文概括任务相关要求；后续规则更新时复核原页面。

## 1. 设计目标

气泡是随文字长度、行数变化的背景组件。源 PNG 是可伸缩的基础皮肤，不是最终比例固定的横幅。先给文字安排完整、可读的底板，再安排角色和挂饰。用户说“主体更小”时，区分角色/装饰与整个气泡；整图缩小并加透明留白，常会缩坏正文区、增大外部空隙。

本次猫咪素材属于贴纸类：主要元素位于边缘，搭配简洁气泡框。保留角色姿态、标志性细节与原图色调，围绕正文重排。用户要求保持原像素时，拆层、等比缩放与重排比重新生成可控；需要新创作时按用户选择及宿主工具规则处理。

## 2. 官方规则及其用途

来源：[气泡结构](https://effect.douyin.com/content/pwik2f7v/pwdsypki#02c6bab2)、[格式与阅读体验](https://effect.douyin.com/content/pwik2f7v/pwdsypki#f546147c)。

| 项目 | 官方要求或参考 | 执行含义 |
|---|---|---|
| 静态上传 | 一张主态 PNG，不超过 198×162 px，不大于 2M | 最大尺寸不是固定画布/比例；脚本按 2,000,000 字节保守检查 |
| 像素整除 | 本任务上传界面明确宽高需被 3 整除 | 不把屏幕截图像素当作源资源像素 |
| 文字字号 | 默认 51 px，不可调整 | 先预留正文空间，不能靠缩正文迁就细横条 |
| 文字保护区 | 参考 72×72 px | 保留可读底板；并不表示所有文字框只能 72 px 宽 |
| 正文位置 | 视觉居中 | 综合底板和装饰判断，不机械取 PNG 外接框中心 |
| 内部文字间距 | 左右大于 24 px，上下大于 18 px | 文字与气泡内部边界保持距离，计入描边厚度 |
| 对比度 | 正文与背景至少 4.5:1 | 检查文字覆盖区的纹理变化，不只取整图平均色 |
| 实体高度 | 120 px 为基础，一般不超过 135 px | 设计参考，不是每张图必须写死 120 px |
| 圆角 | 24 px 为基础，可灵活调整 | 结合原风格保持完整轮廓 |
| 描边 | 3–6 px 为佳，可微曲/抖动 | 避免过细、拉伸断裂 |
| 主装饰 | 通常不超过 102×102 px；建议一个主体 | 放固定区域，避让正文和伸缩带 |
| 次装饰 | 通常不超过 48×48 px；一般不超过两种 | 月牙、珠链等紧凑组织，减少抢字 |
| 装饰外伸/间距 | 上下不超过 36 px，左右不超过 42 px | 控制相邻消息的空隙，与内部文字留白不同 |

用户实际报错将左右阈值写为 40 px，文档为 42 px。预检采用 40 px 保守阈值，同时保留文档原值，不将差异当成已知内部算法。

示意中 12 pt 对应 36 px、14 pt 对应 42 px，为三倍资源像素关系。源图坐标、网页截图像素和设备显示像素分别记录。不能照着浏览器截图大小缩放素材，也不能把 alpha 检测的某个猜测当成官方规则。

### 动态资源

官方格式为一张主态 WEBP，1 秒循环、30 FPS；动画不影响拉伸区，元素位移小于 18 px。仍需满足阅读、尺寸与文件大小要求。静态脚本不证明动态逐帧合规；需检查帧序列、循环接缝、alpha 和全部动态位置。

## 3. 点九、文字框与装饰

来源：[气泡拉伸](https://effect.douyin.com/content/pwik2f7v/pwdsypki#1e588c64)、[上传流程](https://effect.douyin.com/content/pwik2f7v/pwdsypki#7c7a4b17)。

通用九宫格中，四角保持尺寸，上下中段随宽度伸缩，左右中段随高度伸缩，中心随两轴伸缩。抖音要求预想切图位置并模拟长文本、多行文本；编辑器支持拖动切线、单独拖动文本框和选择文字色值。

- 猫脸、月牙、珠链等放进固定角落；需要时调整位置/大小。
- 伸缩带穿过平整背景及连续边框，避免细节、密集纹理、尖角、肢体被拉变形。
- 文字框独立于伸缩区配置，完整落在可读底板内并留足内边距。
- 切线可拖动，不是固定三等分。报错提及三分位置检测空隙，不足以推断固定切线或完整平台算法。
- 纸纹被拉成条纹时，降低伸缩区纹理对比、重构低频背景或换切线。细节主要由固定装饰保留，不能强拉整张插画。

通用机制参考 Android 官方 [NinePatch drawables](https://developer.android.com/develop/ui/views/graphics/drawables#nine-patch) 和 [Draw 9-patch](https://developer.android.com/studio/write/draw9patch)。Android 一像素黑线标记格式不等同于抖音上传格式；抖音上传 PNG 后在编辑器配置。

## 4. 从原图到交付

### 诊断确切文件

核对实际上传文件名称、大小、RGBA/alpha 分布、实体底板高度。分别标记底板、主装饰、次装饰、正文区、伸缩带和外围透明空间。只有尺寸/透明边框报告，不能证明可读。

本次早期修边版为 198×87 px，中心红色底板只有 27 px，米白只有 36 px，都小于固定 51 px 正文。字号加上下各 18 px 已约 87 px；规范要求“大于”，实际还要留余量，并结合行高和 72×72 参考区。87 px 是设计估算，不是官方规定的最小实体高度。

### 结构重排

先安排正文、内部留白与底板，再放装饰。角色等比缩小，保持姿态；改变底板比例时只调整背景结构。外伸与内部文字留白分别检查。原像素重排可能需要用源纹理重建底板边缘，应如实说明保留的角色像素、新轮廓与弱化的纹理，不能称整图无损。

### 导出和本地验证

导出透明 PNG；边长被 3 整除且在上限内。记录配置 JSON：源尺寸、四条切线、文字框、保护区、正文色、底板范围、描边宽度。坐标使用源图像素，并声明右下是否包含。

预检检查真实 alpha、文字区域透明度、对比度和声明的内边距；在三分位置及邻近像素做保守扫描。分别用 alpha≥128 和 alpha=255，可暴露近乎不透明像素的差异，但这不是已知抖音算法。不能在空白处添加微弱像素伪造通过。

按切线渲染短字、长句、多行，正文固定 51 px；比较四角像素确认尺寸保持。人工检查边框、纹理接缝、压字和深浅背景。预览可用本机中文字体，实际字体和行高以平台为准。

### 平台验证

在授权范围内上传对应 PNG，分别配置切线/文本框及文字色后预览。检查单字、短句、长句、多行、深浅模式。没有平台访问或上传权限时，交付本地结果与坐标，实际平台验证标为待完成。

把“格式合规”“本地伸缩验证”“平台预览通过”分开报告。只有实际看到平台结果才能宣称平台切图通过。发布/提交审核按用户授权处理。

## 5. 本次完成版配置

两图均 198×162 px，实体高度 120 px。猫与挂饰由用户原图像素拆分后等比缩放；底板轮廓重排，使用源图色调和弱化纹理，避免长句拉出条纹。

| 配置 | 源像素坐标 |
|---|---|
| 左/右竖切线 | x=72 / x=144 |
| 上/下横切线 | y=84 / y=108 |
| 文字框 | 左37，上54，右155，下126；宽118，高72 |
| 参考保护区 | 左60，上54，右132，下126；72×72 |
| 红款文字色 | #FFFFFF |

示例坐标不是所有气泡的通用固定值；右下边界不包含；上传 PNG 不含示意线。

本地最低文字背景对比度：红款约 7.87:1，米白款约 13.22:1。扣除 3 px 描边后的声明内边距：红款左27/上21/右25/下21 px；米白款左27/上21/右33/下21 px。三分位置及邻近像素的外侧扫描最大值：上下31 px，左右15 px。

短字、长句、多行本地模拟已完成，四个固定角落像素保持。尚未在用户账号的抖音上传编辑器实际验收，不宣称平台通过。

## 6. 故障定位

| 现象 | 修复对象 |
|---|---|
| 尺寸/格式不符 | 核对是否误传高清图、旧版、预览；检查 PNG、大小、整除和边长 |
| 元素与气泡间距过大 | 主体/装饰布局、过大的透明留白、报错采样处真实像素 |
| 文字越出色块或压猫 | 文字框、实体高度、内部留白 |
| 猫、月牙或尖角变形 | 图案跨入伸缩带、固定区域不足 |
| 底板条纹/接缝 | 颗粒单向/双向拉伸，切线两侧像素不兼容 |
| 本地与平台数值差异 | 确切上传文件、源坐标与截图缩放、alpha、实际平台预览 |

明确区分当前上传 PNG、预览和示意图。旧版保留，但与当前上传入口隔开，减少误传。
